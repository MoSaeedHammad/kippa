# Web App i18n (English + Arabic, RTL) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every user-facing string in `frontend/web` becomes translatable via react-i18next, shipping English + Arabic with full RTL support.

**Architecture:** `i18next` initialized once in `src/i18n/index.ts` with statically imported per-feature JSON namespaces. A `LanguageProvider` (modeled on the existing `ThemeModeProvider`) owns the active language, persists it to localStorage, syncs `i18n.changeLanguage()`, `document.documentElement.dir`, and the MUI theme `direction`; an Emotion cache swap (`stylis-plugin-rtl`) mirrors the layout. Keys are TypeScript-checked via `CustomTypeOptions` augmentation; a vitest test keeps `en` and `ar` key sets identical.

**Tech Stack:** react-i18next, i18next, stylis-plugin-rtl, date-fns locales (v4), MUI X pickers, vitest.

**Spec:** `docs/superpowers/specs/2026-09-29-web-i18n-design.md`

## Global Constraints

- Scope is `frontend/web` ONLY. Do not touch `frontend/landing`, `backend/functions`, or `packages/design-system` appearance. Landing/backend strings stay English (design decision).
- Backend-owned content is NOT translated: Firestore-stored notification titles/bodies, AI prompt internals (`systemPrompt`, tool descriptions sent to the model), user-entered data.
- Namespaces mirror feature areas: `common`, `appShell`, `auth`, `dashboard`, `transactions`, `shared`, `sharedBalance`, `sharedAccounts`, `household`, `activity`, `notifications`, `accounts`, `categories`, `cards`, `budgetCycles`, `fastEntry`, `pendingTransactions`, `reconciliation`, `loans`, `ai`. `common` = cross-feature UI words (Save, Cancel, Delete, Retry, Loading…).
- Key naming: `section.context[.qualifier]`, e.g. `profileMenu.signOut`, `transactions.table.emptyState`. Keys hold English copy that is readable in context — never hash keys.
- Arabic copy must use the terms in `UBIQUITOUS_LANGUAGE.md` consistently (e.g. household = بيت مالي? — decide per term during extraction and keep a glossary section in `src/i18n/README.md` as terms are translated; reuse translations across namespaces).
- `sx` usage stays layout/positioning only (AGENTS.md). During extraction, convert hard-coded `left:`/`right:` in `sx` to logical properties (`insetInlineStart`, `marginInlineStart`, `paddingInlineEnd`, …) in the file being touched — this is a per-file standing rule, plus a final sweep in Task 15.
- Icons only via `AppIcon`; typography via named variants — do not introduce new ad-hoc `sx` typography while replacing strings.
- `resolveJsonModule: true` is already set in `tsconfig.app.json`. Workspaces are npm; run commands from `frontend/web` unless noted.
- Every task ends with: `npm run typecheck` PASS, `npx vitest run` PASS (from `frontend/web`), commit.
- Arabic numerals/dates use `ar-EG` conventions via `date-fns/locale` `arEG` (Arabic-Indic digits) — decided in spec.

- `src/i18n/index.ts` — i18next init; re-exports nothing else. Imports `resources.ts`.
- `src/i18n/resources.ts` — the `resources` object (en/ar → namespace → JSON). Imported by both `index.ts` and the parity test.

- [ ] **Step 2: Create the language context (mirrors themeModeContext)**

`src/contexts/languageContext.ts`:

```ts
import { createContext } from 'react';

export const SUPPORTED_LANGUAGES = ['en', 'ar'] as const;
export type AppLanguage = (typeof SUPPORTED_LANGUAGES)[number];
export type AppDirection = 'ltr' | 'rtl';

export const LANGUAGE_STORAGE_KEY = 'kippa.lang';

export const LANGUAGE_DIRECTIONS: Record<AppLanguage, AppDirection> = {
  en: 'ltr',
  ar: 'rtl',
};

export function readStoredLanguage(): AppLanguage | null {
  try {
    const raw = localStorage.getItem(LANGUAGE_STORAGE_KEY);
    if (raw && (SUPPORTED_LANGUAGES as readonly string[]).includes(raw)) {
      return raw as AppLanguage;
    }
  } catch {
    // localStorage unavailable (private mode) — fall through
  }
  return null;
}

export function readBrowserLanguage(): AppLanguage | null {
  const nav = typeof navigator !== 'undefined' ? navigator.language : undefined;
  if (!nav) return null;
  if (nav.toLowerCase().startsWith('ar')) return 'ar';
  if (nav.toLowerCase().startsWith('en')) return 'en';
  return null;
}

export function storeLanguage(lang: AppLanguage): void {
  try {
    localStorage.setItem(LANGUAGE_STORAGE_KEY, lang);
  } catch {
    // non-fatal
  }
}

export interface LanguageContextValue {
  language: AppLanguage;
  direction: AppDirection;
  setLanguage: (lang: AppLanguage) => void;
}

export const LanguageContext = createContext<LanguageContextValue | null>(null);
```

- [ ] **Step 3: Create the provider (mirrors ThemeModeProvider)**

`src/hooks/LanguageProvider.tsx`:

```tsx
import React, { useCallback, useEffect, useState } from 'react';
import {
  LanguageContext,
  LANGUAGE_DIRECTIONS,
  readBrowserLanguage,
  readStoredLanguage,
  storeLanguage,
  type AppDirection,
  type AppLanguage,
} from '@/contexts/languageContext';
import i18n from '@/i18n';

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const [language, setLanguageState] = useState<AppLanguage>(() => {
    return readStoredLanguage() ?? readBrowserLanguage() ?? 'en';
  });

  useEffect(() => {
    void i18n.changeLanguage(language);
    const dir = LANGUAGE_DIRECTIONS[language];
    document.documentElement.lang = language;
    document.documentElement.dir = dir;
  }, [language]);

  const setLanguage = useCallback((lang: AppLanguage) => {
    setLanguageState(lang);
    storeLanguage(lang);
  }, []);

  const direction: AppDirection = LANGUAGE_DIRECTIONS[language];

  const value = React.useMemo(
    () => ({ language, direction, setLanguage }),
    [language, direction, setLanguage],
  );

  return <LanguageContext.Provider value={value}>{children}</LanguageContext.Provider>;
}
```

`src/i18n/locales.test.ts`:

```ts
import { describe, expect, it } from 'vitest';
import { flatten } from './flatten';
import { resources } from './resources';

const namespaces = Object.keys(resources.en) as Array<keyof typeof resources.en>;

describe('locale key parity', () => {
  it.each(namespaces)('ar and en have identical keys in "%s"', (ns) => {
    const enKeys = flatten(resources.en[ns]).sort();
    const arKeys = flatten(resources.ar[ns]).sort();
    expect(arKeys, `missing in ar/${String(ns)}: ${enKeys.filter((k) => !arKeys.includes(k)).join(', ')}
extra in ar/${String(ns)}: ${arKeys.filter((k) => !enKeys.includes(k)).join(', ')}`).toEqual(enKeys);
  });

  it('en and ar contain no empty strings', () => {
    for (const lang of ['en', 'ar'] as const) {
      for (const ns of namespaces) {
        for (const [key, value] of flatten(resources[lang][ns])) {
          expect(typeof value, `${lang}/${String(ns)}:${key} is not a string`).toBe('string');
          expect((value as string).trim().length, `${lang}/${String(ns)}:${key} is empty`).toBeGreaterThan(0);
        }
      }
    }
  });
});
```

`src/i18n/flatten.ts`:

```ts
type Json = string | number | boolean | null | Json[] | { [k: string]: Json };

/** Flattens nested JSON into dotted key paths, skipping arrays (plural suffixes are flat keys). */
export function flatten(obj: Json, prefix = ''): Array<[string, unknown]> {
  const entries: Array<[string, unknown]> = [];
  for (const [k, v] of Object.entries(obj)) {
    const path = prefix ? `${prefix}.${k}` : k;
    if (v !== null && typeof v === 'object' && !Array.isArray(v)) {
      entries.push(...flatten(v as { [key: string]: Json }, path));
    } else {
      entries.push([path, v]);
    }
  }
  return entries;
}
```

### Task 3: app-shell + common components extraction

Extract every user-facing literal in the app shell. By convention from here on, each extraction task follows the same 6 steps (shown once here; repeat per task):

1. **Write `en` JSON** for the namespace(s) with every literal found in the files below.
2. **Write matching `ar` JSON** (use the glossary).
3. **Replace literals with `t()`** — `const { t } = useTranslation('<ns>');` in components; for non-component modules use `i18n.t('<ns>:key')` from `import i18n from '@/i18n'`.
4. **Run typecheck + tests** — `cd frontend/web && npm run typecheck && npx vitest run` — expected PASS (typed keys catch typos; parity test catches missing Arabic).
5. **Manual spot check** in dev server: English unchanged; Arabic renders RTL correctly for the touched screens.
6. **Commit** with message given in the task.

- Modify: `src/components/app-shell/AppShell.tsx`, `BottomNav.tsx`, `TopBar.tsx`, `SideNav.tsx`, `QuickNavMenu.tsx`, `AppLoadingScreen.tsx`, `src/components/OfflineBanner.tsx`, `src/features/shared/components/PageHeader.tsx`, `CurrencySelect.tsx`, `InfoTooltip.tsx`, `ForeignBalanceTooltip.tsx`, `AccountPicker.tsx`, `EmptyLayout.tsx`, `CardHeading.tsx`
- Namespace: `appShell` for nav/shell, `shared` for the shared feature components.

**Standing translation rules (apply in every task):**

- Interpolation: `t('household.members.current', { count: n })` → JSON `"current_one": "{{count}} member"`, `"current_other": "{{count}} members"`. Use `_one`/`_other` plural suffixes for ANY string with a count. Arabic plurals also use `_one`/`_other`/`_zero` — add `_zero` when Arabic copy needs "no members" style copy; i18next handles the selection.
- aria-labels and tooltips count as user-facing — translate them too: `<IconButton aria-label={t('topBar.openMenu')}>`.
- Strings in constants arrays (nav items, option lists): replace the `label: 'Home'` field with `labelKey: 'sideNav.home'` and resolve with `t(labelKey)` at render time. Do NOT store translated strings in module constants.
- Template literals with user data: `` `ID: ${id.slice(0,8)}...` `` → `t('profileMenu.spaceId', { id: id.slice(0, 8) })` with `"spaceId": "ID: {{id}}…"`.
- Error strings passed to snackbars: key at the call site (`enqueueSnackbar(t('ns.key'))`); if the string is produced in a `libs/` module, apply Task 13's error-key pattern instead of importing `t` there.
- Leave dev-facing strings untranslated: `console.*`, code comments, test IDs (`data-testid`), version strings.

Example transformation (real code from `ProfileMenu.tsx:159`):

```tsx
// before
Current space
// after
{t('profileMenu.currentSpace')}
```

with en `"currentSpace": "Current space"`, ar `"currentSpace": "الفضاء الحالي"`.

**Error-key pattern** (spec §String extraction): throwing sites emit stable keys; display sites resolve them.

```ts
// libs — before
throw new Error('Cannot delete a category that is in use');
// libs — after
export class AppError extends Error {
  constructor(public readonly messageKey: string, public readonly params?: Record<string, unknown>) {
    super(messageKey);
  }
}
throw new AppError('common:errors.categoryInUse');
```

```tsx
// display site — after
} catch (err) {
  const message = err instanceof AppError ? t(err.messageKey, err.params) : t('common:states.error');
  enqueueSnackbar(message, { variant: 'error' });
}
```

Create `src/libs/AppError.ts` with the class above; migrate existing `throw new Error('user-facing prose')` call sites to `AppError` and every `catch` that surfaces a snackbar/UI message to the pattern shown. Errors that only hit `console` stay plain `Error`.
